## Что это
**Библиотека тафсиров** — статический веб-сайт для чтения Корана, переводов и
тафсиров с телефона и десктопа. Без сборки и фреймворков: один `index.html`
(ванильный JS) + данные в `data/` (JSON). Хостится как статика (GitHub Pages).

## Как запустить / проверить
- Локально: `python3 -m http.server 8000` в корне → http://localhost:8000/
  (открывать `file://` нельзя — браузер блокирует загрузку JSON; для offline есть
  `.js`-зеркала, см. ниже).
- Тестов нет; проверка — глазами в браузере. Питон-скрипты идемпотентны.

## Расположение данных (абстракция источников)
- **Реестр `SOURCES`** в начале `<script>` в `index.html` — для каждого КЛАССА
  ресурса `{baseUrl, pathTemplate}`. Классы: `config`, `coverage`, `warnings`
  (предупреждения об ошибках в источниках), `news` («что нового в библиотеке»), `quran_text`,
  `tafsir_text`, `tafsir_monolith`, `search_index`, `glosses`, `morphology`,
  `about`, `concordance` (индекс корней), `surah_meta` (классификации сур для оверлеев карты хифза),
  `mushaf_glyphs`, `mushaf_fonts`, `mushaf_fonts_r2` (шрифты таджвид-пака на R2),
  **`mushaf_scans`** (webp-страницы скана),
  **`scan_maps`** (карты-списки страниц скана), **`audio_cdn`** (поаятное CDN-аудио
  чтецов для media.js: `{subdir}/{file}`, файл `NNNSSS.mp3` — паддинг у вызывающего),
  `audio` (задел), `arabic_volumes` (задел).
- **Все URL к данным — только через `resolveUrl(class, params)`.** Прямых/«зашитых»
  путей в коде нет. Чтобы перенести класс на другое хранилище, меняется ТОЛЬКО
  `baseUrl` нужного класса в `SOURCES` — вызывающий код не трогается; разные классы
  могут жить на разных базах.
- **Переопределение базы на уровне ИСТОЧНИКА**: поле `dataBase` в записи источника
  в `config.json`. `resolveUrl` применяет его для по-аятных классов источника
  (`tafsir_text`, `tafsir_monolith`, `search_index`, `quran_text`); лёгкие общие
  классы (config/coverage/about/…) остаются локальными. Так тяжёлый источник можно
  держать целиком на R2 (монолит+чанки+индекс), а остальные — в репо. Пример —
  `mawsua_masur` (свод бил-ма'сур, ~120 МБ): данные на R2, в репо НЕ коммитятся
  (`.gitignore`), пересборка — `build_mawsua_masur.py` → split/index/fill/coverage.
- Текущие базы: почти всё `data`; `mushaf_fonts="fonts"`; **`mushaf_scans` →
  Cloudflare R2** (`https://pub-d99a56b61d914461b5864f421a013097.r2.dev`) — см.
  «Сканы на R2» ниже.

## Модель данных (главное)
- Каждый тафсир/перевод/словарь = `{ "<номер_аята>": "markdown-текст" }` по сурам.
- **`config.json` — единственное место правки** метаданных источника. После любой
  правки запусти **`python3 sync_config.py`** → пересоберёт `config.js`.
- Поле `fill` (доля заполненных аятов) **не править руками** —
  **`python3 compute_fill.py`** пересчитывает по данным.
- Поля источника: `id, file, name, nameAr, author, group, kind(quran|translation|
  tafsir|image), lang(ru|ar), era, tags[], year, fill`. Опционально: `about, caution,
  approved, translator, source…` (см. GUIDE §2).
- Группы (`config.json.groups`): quran / translations / russian / modern_ar / classical_ar.
- **Контейнеры (`config.json.containers`) = КОРПУС, один источник из многих слоёв**:
  `{id,name,nameAr,group,note,about}`. Лежат ОТДЕЛЬНО от `tafsirs`, поэтому данные,
  покрытие, поиск, офлайн и пресеты работают с реальными id слоёв — правок в 50+
  мест не потребовалось. Источник попадает в корпус полем `parent: "<id корпуса>"`,
  `core:true` = костяк. Сейчас так собран свод «аль-Мавсуа»: `athar_ru` (рус.:
  5 имамов + Ибн Аббас) и `athar_ar` (араб.: 12 передатчиков + «прочие»
  `athar_misc` + костяк + полный свод = 15 слоёв). ПОРОГ ВЫДЕЛЕНИЯ: отдельным
  слоем идёт передатчик с покрытием ≳15% аятов; остальные сведены в «прочих»
  флагом `merged` в `build_athar.py` (2026-08-14: было 40 слоёв, 25 сведено —
  «Тафсир Аиши» на 5% аятов обещал тафсир, а давал горсть преданий).
  ПОВЕДЕНИЕ: у корпуса СВОЕГО флага нет — «включён» = включён хотя бы один слой
  (`contOn`); галочка корпуса включает/гасит ВСЕ слои разом (`toggleCont`) — он
  задуман как один тафсир, а слои под аятом и так подписаны именами передатчиков.
  Выборочное отключение спрятано за кнопкой ⚙ в строке корпуса (с плашкой-
  предупреждением и «↺ включить всех»), костяк при включённом корпусе не
  снимается (замок), включение любого слоя подтягивает костяк (`toggleContKid`).
  Порядок переставляется единицами показа (`moveUnit`): корпус переезжает целиком.
  Набор «из коробки» (`DEFAULT_ENABLED`): `_arabic`, `kuliev`, `podrostkam`,
  `detyam` и корпус `athar_ru` третьим — позиция задана порядком в `config.tafsirs`.
  В «Выбрано» и в ленте корпус — ОДНА строка/карточка:
  `groupForRender` сводит слои к одной записи, `contEntryHTML` рисует их внутри
  одной карточки (каждый слой — обычным `sourceEntryHTML`, поэтому сноски,
  «развернуть» и ⚠-разборы сохраняются). Слой без текста на аяте пропускается.
  Поле `parent` со ссылкой на ДРУГОЙ ИСТОЧНИК (старые подтафсиры) работает как раньше.

## Разметка текста тафсиров (подмножество Markdown, рендер в index.html)
- `**жирный**`, `__жирный__`, `*курсив*`, `` `моно` ``, `# … ####`, `> цитата`,
  списки, таблицы, `---`.
- **ВАЖНО:** одиночное `_подчёркивание_` НЕ курсив (только `*звёздочки*`).
- Сноски: `текст[^1]` + отдельной строкой `[^1]: примечание` → список под аятом.
- Карточки: `[[видимое::текст]]` → кликабельное слово с попапом (грамматика).
- **Врезка «смысл аята»** (2026-08-16, для `tabari_bayan_ru`): цитата, начатая
  подписью `> **Смысл аята по ат-Табари:** …`, рендерится не как `.md-q`, а плитой
  `.md-para` (акцентная заливка + метка прописными); подпись
  `> **Смысл аята, сведённый из разбора:** …` даёт `.md-para-sum` (пунктир без
  заливки — там, где своей перифразы у имама нет). Распознаётся по САМОЙ подписи в
  `mdRender`, поэтому синтаксис текстов обычный markdown, а прочие цитаты не задеты.
- Текст HTML-экранируется (произвольный HTML вставить нельзя).

## Текущее состояние и подсистемы (что уже есть в коде)
Подробная история — в `CHANGELOG.md` («новое сверху»). Кратко, последнее сверху:
- **Гидратация ленты — ПЕРВЫЙ ЭКРАН СИНХРОННО** (2026-08-16): тела аятов
  (`.ab-body`) рисуются пустыми и наполняются по IntersectionObserver
  (`setupHydration`). Раньше наполнялись ВСЕ лениво — видимые блоки вырастали
  с 48px уже после показа, и лента дёргалась 1–2 секунды (замер `layout-shift`
  = 0.4 при открытии суры). Теперь `setupHydration(area,enabled,loaded,startAid)`
  синхронно заполняет ~1.6 экрана от целевого аята (на блок выше — для
  прокрутки вверх), остальное лениво; стало 0 сдвигов. При правке рендера
  ленты СЛЕДИТЬ за этим: любой возврат к «всё лениво» вернёт дёрганье.
  Проверять так: PerformanceObserver по `layout-shift` вокруг `goSurah`.
- **Записи заметки — тадаббур, фаза 3** (2026-08-16): у аята МАССИВ записей
  `noteRecs={"с:а":[{id,t,x,ts,m,g}]}` (типы `NOTE_TYPES`: мысль/вопрос/вывод/
  дуа/связь; `g` — теги записи = сборники). КЛЮЧЕВОЕ РЕШЕНИЕ: старый `notes`
  НЕ отменён, он стал ПРОЕКЦИЕЙ (`noteProject`) и переписывается при каждой
  правке — поэтому поиск, слой `_notes`, backlinks, счётчики, экспорт и
  СТАРЫЕ УСТРОЙСТВА работают без правок, а разовой миграции нет (записи
  создаются лениво из `notes` в `noteRecs(s,a)`). Одна запись типа «мысль» →
  проекция = чистый текст; несколько → с подзаголовками. При расхождении
  (notes правили в обход) побеждает `notes`, записи схлопываются в одну.
  `saveNote` при ОДНОЙ записи правит её (сохраняются дата/тип/теги), при
  нескольких молчит — интерфейс там показывает список (`noteFieldHTML`), а не
  textarea. Слияние в `applyImport` — по `id` записи, после чего проекция
  ПЕРЕСОБИРАЕТСЯ (иначе объединённый набор разошёлся бы с плоским текстом и
  схлопнулся). Экран «Мои заметки» получил вид «дневник» (`ST.notesDiary`) и
  фильтры `ST.notesType`/`ST.notesTag`.
- **«Работа над аятом» — верстак** (2026-08-16, вырос из Study Mode `openStudy`):
  полноэкранный оверлей одного аята, глобал `STU={s,a,tool,sheet,mark}`,
  вход — лист аята. РАСКЛАДОК ДВЕ, и это осознанно (десктоп — основной сценарий
  мейнтейнера, телефон — основной у читателя), граница — `wbWide()`
  (`matchMedia(min-width:900px)`, НЕ innerWidth: он врёт в headless):
  ≥1181px — четыре зоны в ряд (`.wb-srcs` источники · `.wb-read` чтение ·
  `.wb-work` работа · `.wb-rail` рельса); 900–1180px — колонка источников
  уступает место тексту (её заменяют чипы + кнопка «Источники», класс
  `.only-narrow`); ≤899px — `.wb-work` становится НИЖНИМ ЛИСТОМ
  (`data-sheet` 0/1/2 на оверлее), рельса ложится доком. Инструменты —
  `WB_TOOLS` (srcs/note/tags/words/roots/links, клавиши 1…6), содержимое
  рисует `wbRenderWork`. Поток источников переиспользует `groupForRender` +
  `sourceEntryHTML`/`contEntryHTML` (сноски, ⚠, «развернуть» работают), пустые
  источники пропускаются. Колонка источников показывает ВКЛЮЧЕНО и «Есть у
  этого аята» (из `covSourcesForAyah`) — включение прямо там. Маркер слов внутри:
  при `STU.mark` общий обработчик кликов по `[data-loc]` красит слово вместо
  грам-карточки (`wbMarkTap`), строка аята перекрашивается точечно
  (`wbPaintAyah`, НЕ перерисовкой колонки — иначе улетает прокрутка).
  СРАВНЕНИЕ (`STU.cmp` — массив id любой длины): ширины колонок считает
  `wbCmpLayout` — вес = √(длина/медианы) в 0.75…2, зажим 260…640px, остаток
  делится между неупёршимися; не влезло — класс `strip` (лента, ширину задаёт

## Проверка headless (нет node/playwright, есть google-chrome-stable)
Сервер: `python3 -m http.server 8000`. Снять DOM/скриншот:
`google-chrome-stable --headless --no-sandbox --disable-gpu --hide-scrollbars
--window-size=440,950 --user-data-dir=<свежий> --virtual-time-budget=12000
--run-all-compositor-stages-before-draw --dump-dom|--screenshot=out.png URL`.
- Состояние через URL: `#сура` (хэш) и `?param` (query) — **query идёт ПЕРЕД хэшем**:
  `?x=1#103`, не `#103?x=1` (иначе попадёт во фрагмент).
- Для экранов, требующих действия (грам-карточка, попап, поиск, редактор, режим
  источника) — временно вставить авто-вызов в конце `loadConfig` (`setTimeout(...)`),
  снять, и ОТКАТИТЬ файл (md5/бэкап). Безопаснее — временная КОПИЯ страницы
  (`_test.html` в корне, в коммит не идёт): index.html тогда вообще не трогается.
- Пара граблей: `window.innerWidth` врёт (clamp ~500) — адаптив проверять через
  `matchMedia`; динамический IntersectionObserver после JS-ре-рендера под
  virtual-time часто не срабатывает — для виртуализации грузить целевую суру
  естественной загрузкой; `let`-глобалы (ST, COV) не висят на `window`, а
  function-declaration (resolveUrl, doSearch) — доступны.
- JS-синтаксис без браузера: извлечь большой `<script>` и `node --check`.
- **Чистая функция — проверять в node без браузера**: вырезать её текст из
  `<script>` по имени (`function имя(` + счёт скобок) и выполнить через
  `new Function(...)`. Так проверен рендер врезки: `mdRender` тянет за собой
  `mdInlineBasic`, `mdInline`, `mdBlockStart`, а `esc` и `mdTableStart` заменяются
  заглушками (первый лезет в `document`). Быстрее любого headless-прогона.
- **Вид элемента — без запуска приложения**: собрать страницу из всех `<style>`
  index.html + готовый HTML от `mdRender`, поставить `data-theme` на `<html>` и
  `<body>` и снять скриншот. Так видно и светлую, и тёмную тему без localStorage,
  включения источников и ожидания загрузки данных.
- **Сценарий в headless — ЖДАТЬ готовности, а не `setTimeout`**: инициализация
  (`loadConfig` → coverage → warnings) заканчивается позже любой разумной паузы
  и перекрывает ранний вызов (экран возвращается на Главную). Рабочий приём —
  опрос: `setInterval` до `typeof goAyah==="function" && CONFIG.tafsirs.length`,
  затем до `.ayah-block`, затем до нужного узла оверлея; результат отдавать через
  `document.title` и снимать `--dump-dom`-ом. И ПЕРЕСОБИРАТЬ `_test.html` после
  каждой правки index.html — иначе проверяется старая копия (обжигались).
- **Дёрганье вёрстки меряется, а не оценивается на глаз**: PerformanceObserver
  по `layout-shift` вокруг `goSurah`/`goAyah` (порог «незаметно» — 0.1).

## Проверка источника на вероучительные отклонения (предупреждения)
Редакторский слой `data/warnings.json` (текст источника НЕ меняется): значок ⚠ + рамка
у аята, кнопка «⚠ Ответ на заблуждение» + плашка `.warn-inline`, свод в паспорте ℹ
(`aboutWarnings`) + краткая заметка `editorNote` в `config.json`. Уровни: `critical`
🔴 (искажение хукма/акыды), `moderate` 🟡 (смысловой сдвиг/послабление), `minor` 🔵
(тональность). Зелёный НЕ используется (он — «одобрено ✓✓»).
**Методика проверки и переиспользуемый список маркеров/флагов — в `GUIDE.md §9`.**
Кратко: понять «отпечаток» источника → скан по маркерам всего корпуса → триаж
(маркер ≠ проблема) → чтение кандидатов в полном контексте (параллельные субагенты
по темам) → калибровка цвета. Ассистент НАХОДИТ и выдаёт кандидатов (адрес+цитата+
приём+цвет), богословский текст пишет мейнтейнер; такфир не выносим. Ловушки: свёрнутый
повтор в изоляции безобиден на вид; следовать перекрёстным ссылкам («см. аят N»);
современный автор как ЕДИНСТВЕННЫЙ далиль и обратная ссылка на классика — флаги.
3-й проход — корзины по ПРЕДМЕТУ насса, не по лексике (GUIDE §9): сыфаты (тавиль/ташбих),
тавалли/бараʼ, кадар-«вселенная идёт навстречу», историзация хукма, совр. авторы по
конструкции; библейская цитата-довод — усилитель. Калибровка: «хукм + светский суд» =
красное по умолчанию (передача юрисдикции; смягчение меры внутри шариата — жёлтое);
в разборе разграничивать qatʿи/занни; отмечать и верно переданное.
Обкатано на `alyautdinov` (модернизм; ~30+ аятов; источник временно `hidden:true`).

## Рабочие правила
- Меняешь `config.json` → запусти `sync_config.py`. Меняешь данные источника →
  `compute_fill.py` И `build_coverage.py` (индекс покрытия для счётчика «Тафсиров: N»,
  списка у аята, режима источника и карты покрытия). Не редактируй `config.js`,
  `fill` и `coverage.json` вручную.
- `data/_sources/` в `.gitignore` — туда кладём сырьё/промежуточное, в коммит не идёт.
- Коммиты и changelog — по-русски, «новое сверху». Коммитить/пушить — только по
  просьбе пользователя.
- Для inline-обработчиков в HTML экранируй значения через `escAttr()`.
